# ФИНАЛЬНЫЙ ОТЧЁТ: Синхронизация v2 с эталоном v1

## Выполненные задачи

### 1. Документация эталона v1
**Файл:** `WB_API_REFERENCE_V1.md`

Создана полная документация того, как старый биддер v1 получает статистику:
- URL: `https://advert-api.wildberries.ru/adv/v3/fullstats`
- Метод: `GET`
- Параметры: `ids` (через запятую), `beginDate`, `endDate` (YYYY-MM-DD)
- Структура ответа: список кампаний с полем **`stats`** (не `days`!)
- Нормализация: разворачивание `stats` в плоский массив

### 2. Синхронизация backend_v2 с эталоном v1
**Файл:** `backend_v2.py`

- ✅ Использует `WildberriesClient` (как в эталоне)
- ✅ Параметры совпадают: `ids`, `beginDate`, `endDate`
- ✅ Добавлено детальное логирование структуры ответа (без токенов)

### 3. Исправление нормализации в collectors_v2
**Файл:** `wb_bidder/collectors/collectors_v2.py`

**Ключевые исправления:**
- ✅ Использует поле **`stats`** (как в эталоне v1), а не только `days`
- ✅ Нормализация полностью соответствует `_normalize_fullstats()` из старого кода:
  - Извлечение `advertId`
  - Разворачивание `stats` в плоские записи
  - Нормализация даты (обрезание времени)
  - Вычисление производных метрик (`cr`, `cpo`)
  - Поддержка `days` для совместимости

### 4. Исправление агрегации в full_analysis
**Файл:** `full_analysis.py`

**Ключевые исправления:**
- ✅ Правильный маппинг `campaign_id` → `item_id` через `CONTROLLED_ITEMS`
- ✅ Поддержка обоих форматов полей: `spend` (из v1) и `spent` (из v2)
- ✅ Корректная агрегация данных по `item_id`

### 5. Создан скрипт для мульти-проверки
**Файл:** `debug_multi_campaigns.py`

**Функциональность:**
- ✅ Отбор активных кампаний (где v1 видит clicks > 0)
- ✅ Сравнение агрегированных сумм между v1 и v2:
  - `clicks_sum`
  - `orders_sum`
  - `spent_sum`
- ✅ Вывод подробной строки для каждой кампании:
  ```
  item_id=..., campaign_id=... | v1(clicks=X1, orders=Y1, spent=Z1) | v2(clicks=X2, orders=Y2, spent=Z2) | status=OK/BUG
  ```
- ✅ Определение статуса на основе сравнения:
  - **OK**: если обе версии дают сопоставимые значения (погрешность ±2 клика, ±1 заказ, ±0.01 руб)
  - **BUG**: если v1 видит данные, а v2 - нет, или значения сильно расходятся
- ✅ Итоговая сводка с количеством OK/BUG кампаний
- ✅ Список BUG-кампаний с детальной информацией для отладки

## Использование

```bash
# Установить базовый URL backend_v2
$env:WB_API_V2_BASE_URL="http://localhost:8002"

# Запустить проверку
python debug_multi_campaigns.py
```

Скрипт:
1. Загрузит кампании из `controlled_items.json` и `config.py`
2. Отберёт активные кампании (где v1 видит clicks > 0)
3. Для каждой кампании сравнит v1 и v2
4. Выведет подробную таблицу результатов
5. Покажет итоговую сводку с количеством OK/BUG кампаний
